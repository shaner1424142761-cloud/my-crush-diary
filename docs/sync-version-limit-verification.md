# 2026-10-27 同步失败修复

## 线上证据
用户页面显示保存失败且本机备份仍保留。使用现有会话只读打开首页，GET /diary 正常；重试用户已经录入的待同步内容时，PUT /diary 返回 502。后端新增脱敏诊断仅记录方法、HTTP 状态及固定分类，确认上游 JSONBin PUT 返回 403、分类 version-limit。没有记录令牌、私密内容或上游原始错误文本。

原后端在每次保存时发送 X-Bin-Versioning: true。JSONBin 官方更新接口文档说明版本数量有限（https://jsonbin.io/api-reference/bins/update）。这导致读正常、写失败，与用户现象吻合。

## 修复
- 日常 PUT 改为 X-Bin-Versioning: false，避免继续创建版本；保持原 Bin、原数据、账号权限及写入前的最近三份 Durable Object 快照。不发送 DELETE 或清空记录。
- GET 后比较云端记录与有效合并结果，仍有本机变更时显示待同步，不再误报「数据已最新」。
- PUT 响应须确认包含本机更改，才显示「数据已保存」。返回内容缺少待上传分数时保留备份及待同步状态。
- 各页面增加「重试同步」，按钮在上传或锁定时禁用；不同账号仍使用独立备份。

## 验证
- 新测试先复现版本到顶写入失败、拉取误报及漏确认问题，然后修复；完整单元测试 99/99 通过。
