# Two-person Schedule Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a shared weekly calendar with recurring schedules, single events, occurrence exceptions and deadlines.
**Architecture:** A shared schedule module validates and expands wall-clock dates. Existing record merge and backup handle schedules and tombstones. A native HTML page renders the week and edits records through the existing authenticated sync API.
**Tech Stack:** HTML, CSS, JavaScript, Node test runner, Cloudflare Worker.
**Spec:** ../specs/2026-10-27-schedule-design.md

## Global Constraints
- Keep the existing login, backup and sync flows; no new external services or dependencies.
- All schedule wall-clock values are Asia/Singapore (UTC+08:00).
- Both users may edit schedules; YYF, ZXR and shared ownership are explicit.

## Review Focus
- A moved occurrence must show in its destination week and disappear from its original slot.
- A stale device must not resurrect deleted entries or cancel a newer exception.
- Changing devices' timezone must not shift displayed days or DDL countdowns.
- Invalid dates and end-before-start intervals must fail before saving.
- Account changes and failed sync must preserve the existing account isolation.
