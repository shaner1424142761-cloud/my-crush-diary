# YYF / ZXR 双账号与操作权限（待确认）

## 意图与范围

用户是 YYF，对象是 ZXR。希望两人有独立账号，只能在对应位置给对方打分，悄悄话显示发送者。继续实现此前已确认的照片上传和照片墙；本设计是其登录依赖的升级，不取消相册工作。

这是现有登录和同步权限的架构升级。先完成双账号，再让照片模块使用新的登录身份。仍然免费、先本地模拟调试、完整保留旧记录，不推送或更新线上。

## 账号与登录

固定两个账号：账号 ID `yyf` / `zxr`，显示名称 `YYF` / `ZXR`。登录页选择账号并输入各自密码，不新增公众注册、邮箱验证、第三方账号或付费认证服务。

后端分别使用 `YYF_PASSWORD` 与 `ZXR_PASSWORD` Secrets，密码至少 16 个字符，两人应设置不同密码；不把正式密码放到前端、Git 或聊天里。本地使用明确标注的两个模拟密码。

会话仍为 7 天；默认 sessionStorage，记住设备则 localStorage，密码不存储。令牌升级为 v2，签名载荷必须含合法 `sub: yyf|zxr`；后端从签名身份获取操作者，不能相信客户端声称的姓名。旧无身份令牌不能用于新权限接口，迁移后重新登录。

导航显示当前登录账号，保留退出入口；切换账号通过退出并重新登录完成。退出或换身份时旧请求、照片 Blob URL 和上传流程必须失效。

## 打分规则

沿用现有字段，不重命名、不清空两份积分历史：

| 登录者 | 可操作 | 只能查看 |
| --- | --- | --- |
| YYF | ZXR 的得分：`myHistory/myScore` | YYF 的得分：`taHistory/taScore` |
| ZXR | YYF 的得分：`taHistory/taScore` | ZXR 的得分：`myHistory/myScore` |

前端只启用对应加分、扣分和自定义记分控件；自己的得分显示“由对方打分”。后端也必须检查新增记分事件的目标，越权请求返回 403，不能写 JSONBin。

新的积分事件包含稳定 ID，操作者由后端登录身份确认。已有历史事件是不可变记录，不允许通过复用 ID 修改分数、原因、时间或操作者。两人可以看到双方完整历史和总分。

不能通过直接改总分、历史差额、伪造历史作者或整个旧快照绕过权限。迁移前的真实远端总分和差额由远端记录推导和保留；后续总分由授权的去重历史计算，扣分和并发保存规则不退回旧实现。

## 悄悄话

新留言具有稳定 ID，后端给新增留言绑定签名账号身份；客户端不能冒充另一方。前端显示作者、内容和时间，自己的与对方的留言可以使用不同的轻柔配色/位置。导出的留言文本也显示作者。

远端已有留言没有作者的，保留原文和时间，显示“历史留言 · 未标注作者”。不能凭内容猜作者，更不能把全部旧留言归给当前登录者。重复同步不能补写或覆盖旧作者。

新留言按稳定 ID 去重，以免两人在同一分钟发送相同文字时被错误合并；旧留言继续使用原去重方式，避免因迁移重复生成全部历史留言。不新增编辑/删除旧留言功能。

## 其他模块和照片权限

相册、恋爱日记、愿望和纪念日保持共同使用，两人都能查看与操作。照片上传/查看使用 v2 登录令牌，不额外限定只能查看自己上传的照片。无需单独购买认证或照片存储服务。

原照片上传设计里的压缩、容量、旧链接兼容、失败重试和本地先行要求全部保留。只有两人的操作身份和登录配置需要更新。

## 未同步记录与切换账号

备份和待同步内存按账号隔离，不能把 YYF 的未同步留言或记分在 ZXR 登录后改署名、覆盖或清空。旧 `myCrushDiary_backup_v1` 备份保持保留，不删除；现有远端历史继续正常加载。

迁移前没有作者的本机独有待同步内容不能自动认领。检测到与远端不同的旧待同步内容时保留独立备份并提示核对恢复，而不是让当前登录者默默代写。恢复处理不猜留言作者，记分按目标核对账号；这一迁移保护不能阻止正常读取已有云端历史。

存储不可用时保留对应账号的页面内存并持续提示勿刷新/关闭；切换账号不能将这份内存当作另一账号待同步数据。成功同步后才解除待同步提示。

## 验证与交接

用实际本地 Worker/SQLite 和两个独立浏览器会话测试：各自登录、合法给对方加减分、直接请求越权被拒绝、伪造作者或总分无法写入、同时发送相同文字均保留、重试不重复计分、退出中仍在同步、换账号保留各自待同步内容。

对旧云端备份仅做离线保留核对；旧留言不新增猜测作者，原 343 条记录与总分不得丢失。新双账号与后续相册都通过本地验收后，再由用户确认正式密码配置和上线时机。

## 实施顺序

1. 双账号签名身份与后端写入权限。
2. 登录选择、双方打分控件、悄悄话作者与分账号备份。
3. 实际本地双设备权限和迁移回归。
4. 接续已经编写的照片上传计划，把共同密码依赖改为双账号登录。

用户确认本设计后，补充双账号实施计划并修订照片计划依赖，再开始直接实施。
