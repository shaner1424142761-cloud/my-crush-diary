# 免费后端与恋爱记录保护方案

## 用户目标和约束

修复删除记录被同步恢复、扣分被旧总分覆盖、云端写入密钥随网页公开的问题。
继续使用现有 GitHub Pages 网站地址，保留两个人此前的全部记录。
用户没有云服务使用经验，需要逐步指导；不购买付费套餐、不增加新服务费用。
本轮不改网站风格，不新增回忆时间线等产品功能。

已完成的本地同步修复作为后端迁移的基础：永久删除标记、历史分数差额、
上传前成功拉取要求、本机备份，以及取消自动丢弃旧记录的条数限制。

## 方案选择

采用 Cloudflare Workers Free，使用一个 SQLite-backed Durable Object 协调读写，
继续将现有 JSONBin Bin 作为记录的主存储，不创建空 Bin 替换原记录。
GitHub Pages 保留 HTML、CSS 和浏览器脚本；浏览器只连接经过密码保护的 Worker。

另一种方案是把 JSONBin 连接密钥改成每台设备手动输入。
虽然不用新云服务，但浏览器仍直接持有存储密钥，也不能实现统一串行写入。
用户后来接受免费后端并要求指导，因此选择 Worker 方案。
Vercel 或自建服务器不是本轮目标，避免同时维护多种部署方式。

## 免费条件

2026-10-11 核对的官方文档：

- Workers Free：每天 100,000 次请求，每次 10 ms CPU。
  https://developers.cloudflare.com/workers/platform/pricing/
- SQLite-backed Durable Objects 可用于 Free；每天 100,000 次请求、13,000 GB-s，
  免费 SQLite 总存储 5 GB。达到免费限制后对应操作报错。
  https://developers.cloudflare.com/durable-objects/platform/pricing/
- 使用自动分配的 workers.dev 地址，不购买域名，不升级 Workers Paid，
  不引入需要付费套餐的存储类型。
- 现有 JSONBin 自身的请求及容量限制继续适用；不承诺第三方服务无限免费。
  超限或暂时不可用时保留本机待同步内容，不能为保存成功而静默丢弃记录。

两个人的日常访问预计远低于上述请求额度；实际部署还要用真实大小的快照验证 CPU 限制。
不通过开启付费套餐解决性能问题。

## 登录和密钥

两人使用一个共同的网站密码，不引入账户注册、邮件发送或外部身份服务。
首次打开或登录过期时显示密码登录界面，支持显式选择“在这台设备记住我”。
前端不存储密码；仅保存后端签发的、有过期时间的登录令牌。
默认令牌存在 sessionStorage，勾选记住时使用 localStorage，期限为 7 天。

登录密码、会话签名密钥、JSONBin 连接密钥只存于 Worker Secrets。
登录密码须足够长，不放到仓库、GitHub Actions 构建产物、网页源码或错误消息中。
每次读写必须验证令牌签名和过期时间。登出移除令牌并隐藏记录，
不对云端执行删除，也不把登出实现为清空恋爱数据。

登录尝试按 IP 限速，计数由 Durable Object 管理，以免实例重启后限速失效。
密码比较避免按字符提前返回；错误响应不包含输入密码、连接密钥或云端记录。
生产 CORS 只允许现有 GitHub Pages 的 origin；CORS 不作为身份验证。
本地开发另设 localhost origin，仅用于开发配置。

## 后端接口

- `POST /auth/login`：接收密码，成功返回短期登录令牌及过期时间。
- `GET /diary`：鉴权后返回规范化记录；读取操作不迁移、不初始化、不写云端。
- `PUT /diary`：鉴权、验证输入结构，在同一个 Durable Object 中串行完成
  读取最新 JSONBin → 合并 → 备份此前快照 → 写回 → 返回最终合并记录。
- `GET /health`：只返回服务是否已配置，不包含任何秘密或私人记录。

请求与响应设置不缓存。上游请求有明确超时，未知状态的保存显示失败并保留本机内容。
保存重试必须幂等：积分历史按 ID 去重，删除标记保留，同一留言等旧记录仍采用兼容键。
客户端不再使用 `X-Master-Key` 或 `X-Access-Key` 直接访问 JSONBin。

串行处理覆盖整个网络读改写过程，不能仅在内存修改期间加锁。
Durable Object 使用 SQLite 类型，持久化少量限速计数和最近 3 份保存前快照，
不无限积累数据，不设置周期轮询或高频定时任务。
后端使用与浏览器相同的合并规则，避免两端对积分和删除有不同解释。

## 数据兼容和不丢记录

沿用现有字段，新增 `scoreBaseline` 和 `deletedItems`，旧记录可不包含这些字段。
迁移积分时以当前总分减去去重历史之和得到历史差额，保留原总分。
已有永久删除标记优先于旧设备中的同 ID 活跃记录；不凭数组缺项推断删除。
每台设备中的未同步记录仍先与最新云端合并，不直接用服务端快照替换本机备份。

不通过截断数组满足服务容量限制。保存失败明确提示，原记录保留在云端和本机。
云端读取失败、认证失败或记录结构异常时禁止执行覆盖上传。
浏览器启动不会自动把本机备份写回空云端。

已经在仓库外保存一次云端只读快照，并离线逐条核对：
全部 7 类记录、343 条内容在新合并逻辑下完全保留，当前两人总分也保留。
私人快照不能进入 Git 仓库或 GitHub Pages 发布目录。

## 切换顺序和回退

1. 用户注册 Cloudflare 账号，只使用 Free；完成登录后再做部署授权。
2. 本地实现和模拟测试完成，保留旧网站运行；不提前撤销旧密钥。
3. 配置后端 Secrets 并部署；首先对现有 Bin 只读核对条目和总分。
4. 用独立测试 Bin 或模拟上游完成写入验收；不向正式记录添加测试留言或积分。
5. 切换前再次保存最新正式快照；确认本地待同步内容不会丢弃。
6. 前端切换到后端地址，并从公开文件移除存储密钥。
7. 验证两个人的设备登录、显示原记录和后端连通性。
8. 在现有 JSONBin 账号中更换已公开的旧密钥，更新后端 Secret，
   再验证只读连接；旧客户端因此失去写入权限，不能再丢弃新增同步字段。

密钥更换需要现有 JSONBin 账号的所有者操作，不能仅靠改仓库文件完成。
用户需要登录和授权外部账号的步骤，教程逐项标注；不要求把新密钥发到聊天里。

切换出现问题时保留当前云端记录和待同步本机备份，恢复可用的后端版本或配置。
不把旧快照自动覆盖回云端，不重新公开旧密钥。
恢复数据只能在核对差异并得到用户明确指示后执行。

## 验证和交付

- 现有回归测试覆盖扣分、负分、历史差额、去重、删除标记、断网、
  格式错误、页面点击删除，以及超过旧条数限制后保留本机未同步记录。
- 后端增加鉴权失败无上游访问、令牌过期、登录限速、CORS、密钥不回传、
  并行写入后都保留、PUT 失败可重试、读取无写入副作用等测试。
- 使用正式快照进行完全离线迁移核对，不运行真实 PUT 来测试修复。
- 本地浏览器验收登录、登出、两种记住策略、每个页面的读写状态和移动端布局。
- 部署前检查浏览器可发布的文件不包含有效云端密钥和私人快照。
- 交付中文教程，按注册、登录、创建 Worker、配置 Secrets、部署、
  设置后端地址、密钥更换和验收的实际顺序说明操作。
