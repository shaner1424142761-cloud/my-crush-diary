## yyf and zxr's ~~galgame~~ Romance Memoir

v0.1.2

### 本地运行与验证

这是一个不依赖构建工具的静态网站。可从项目目录运行 `python -m http.server 8000`，
然后访问 `http://localhost:8000`。

回归测试使用 Node.js 自带的测试工具，无须安装依赖：

```powershell
node --test
```

测试只连接模拟云端，不读取或写入真实的恋爱记录。

### 数据同步修复

- 愿望与纪念日的删除会留下 `deletedItems` 标记；旧设备的缓存不会在新客户端中复活这些记录。
- 分数由去重后的积分历史与 `scoreBaseline` 历史差额组成。第一次迁移保留原总分，之后的扣分可以正常降低总分。
- 删除标记和历史差额随云端记录及本机备份保存。
- 相册、日记、愿望和纪念日不再因条数上限自动丢弃旧记录。
- 上传前必须成功读取最新云端内容；拉取失败或数据格式异常时只保留本机备份，不覆盖云端。
- 新操作在网络请求前写入本机备份；打开页面不再自动将本机备份上传到空云端。
- 保存请求开启 JSONBin 版本记录。服务有版本数上限，不能代替独立备份。

更新后，两个人都应刷新所有打开的页面。旧客户端不认识新增的同步字段，仍可能覆盖它们。
浏览器直接访问 JSONBin 的读写并非原子操作；两台设备恰好同时保存仍可能发生竞争。
后续后端需要串行处理保存，才能消除这一窗口。

### 密钥保护的待办

目前公开的前端连接配置仍包含旧密钥，安全迁移尚未完成。
计划使用免费的后端保存密钥，保留 GitHub Pages 地址及已有 JSONBin 记录。
切换成功后，应在 JSONBin 账号中更换已公开的旧密钥。仅删除代码中的密钥不会使旧密钥失效。

个人记录快照、连接密钥和环境变量不应提交到 GitHub，也不应放到 GitHub Pages 可发布的目录。
